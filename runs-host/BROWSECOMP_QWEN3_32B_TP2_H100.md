# BrowseComp + Qwen3-32B TP=2（H100）

测试节点：`node2700`；GPU：8×H100 80GB。固定 BrowseComp source-order n680、
temperature 0、seed 2026、context 40960、轨迹预算 36864，以及 300 秒业务预热
+ 1200 秒正式测量。并发为 c192/c256/c320，共四种方法、12 组实验。

PD 方法保持 2P:6D 物理布局：一个 TP=2 Prefill 组 `[0,4]`，三个 TP=2 Decode 组
`[1,5]`、`[2,6]`、`[3,7]`；显存比例分别为 P 0.80、D 0.80/0.80/0.60，
GPU7 同时承载搜索服务。当前新方法沿用 Q high=32、low=8、工具/Direct 1 秒和原表 Host 配置；
原生 Mooncake 保留原生 HiCache/Mooncake 机制。

当前新方法统一使用 D→P Host 总量 512 GiB、P→D Host 总量 256 GiB；两者均为
所有物理 rank 合计，不应按单个 TP=2 逻辑引擎理解。

## 当前新方法路径统计

以下计数限定在正式 1,200 秒窗口，按 `snapshot` / `key` 去重；窗口首尾的在途
snapshot 会使写入、恢复、释放相差少量，不能将差值直接解释为 KV 丢失。

| 并发 | D→P Direct | D→P Slow Host | D→P 重算 | Direct/Slow/重算 | P→D Direct | P→D Host | Host→D 恢复 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 192 | 1,287 | 728 | 0 | 63.87% / 36.13% / 0.00% | 344 | 3,193 | 3,187 |
| 256 | 1,366 | 566 | 105 | 67.06% / 27.79% / 5.15% | 329 | 3,228 | 3,232 |
| 320 | 1,287 | 400 | 353 | 63.09% / 19.61% / 17.30% | 357 | 3,219 | 3,217 |

早先一轮新方法误将 2P:6D 的每 P 容量沿用为 D→P 128 GiB、P→D 32 GiB，
导致物理总量只有 256/64 GiB；这些目录已归档且不计入本表。c192 已按统一
物理总量 512/256 GiB 重跑；c192/c256/c320 均已按同配置完成。

c192 的 D→P Slow Host 写入与 D 源释放均为 728 次，Host→P 恢复与 extent
释放均为 724 次；P→D Host 写入 3,193 次，Host→D 恢复与 extent 释放均为
3,187 次。差值均来自窗口结束时仍在途的 snapshot，不能解释为 KV 丢失。

c256 的 D→P Slow Host 写入、Host→P 恢复、D 源释放和 Host extent 释放均为
566 次。P→D Host 写入 3,228 次，Host→D 恢复与 extent 释放均为 3,232 次：
其中 33 次恢复来自窗口前写入，29 次窗口内写入在窗口后恢复，因此净多 4 次。

c320 的 D→P Slow Host 写入和 D 源释放均为 400 次；Host→P 恢复与 extent
释放均为 402 次，其中 2 次来自窗口前写入。P→D Host 写入 3,219 次，
Host→D 恢复与 extent 释放均为 3,217 次；其中 32 次来自窗口前写入，
34 次窗口内写入在窗口后恢复。
