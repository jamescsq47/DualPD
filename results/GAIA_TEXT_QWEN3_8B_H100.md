# GAIA-text + Qwen3-8B（H100）

测试时间：2026-10-08；节点：`node2700`；GPU：8×H100。候选任务使用
OpenResearcher `gaia_text` 的 103 道纯文本题，固定 source order 循环、seed 2026、
temperature 0、top_p 1、top_k -1、context 40960、轨迹预算 36864、最多 16 轮，
以及 300 秒业务预热 + 1200 秒正式测量。

PD 配置为 4P:4D、TP=1，P=0/2/4/6、D=1/3/5/7。新方法统一使用
D→P Host 总量 512 GiB（128 GiB/P）和 P→D Host 总量 256 GiB（64 GiB/P）。
原生 Mooncake 保留原生共享 segment/HiCache 机制。初始 colocated 筛选显示 KV 压力较低，
因此若 c384 的新方法相对 no-reverse 达到约 2×，正式矩阵采用 c384/c512/c640。

当前新方法正式窗口为 `steady_churn`：1285 条以 final 结束，164 条达到单轮长度上限，
144 条达到 16 轮上限；一轮轨迹占 13.43%，平均轮数 5.86。工具时间中位数 120.10 秒、
P90 420.01 秒，说明该候选明显受公网搜索延迟影响。正式窗口内用数据集唯一 6-gram
交叉扫描未发现串题；一条启动期 warmup 轨迹含可疑的其他题语义，保留作正确性审计，
不计入正式测量。

No-reverse 的正式窗口完成 1,982 条，吞吐为 1.6517 Agent/s；其中 1,597 条以
final 结束，208 条达到单轮长度上限，176 条达到 16 轮上限，另有 1 条达到工具
上下文预算，正式窗口失败为 0。平均/中位/P90 轮数分别为 5.93/5/14。新方法相对
no-reverse 的吞吐比为 **0.8037×**，因此 GAIA-text 不满足 1.8× 的扩矩阵资格。

原生 Mooncake 的正式窗口完成 1,922 条，吞吐为 1.6017 Agent/s，正式窗口失败为 0；
其中 1,528 条以 final 结束，183 条达到单轮长度上限，210 条达到 16 轮上限，另有
1 条达到工具上下文预算。平均/中位/P90 轮数分别为 6.08/5/16。该方法保持 stock
SGLang 的 256GB global segment 与原生 P/D HiCache 机制，没有套用新方法的 Host
arena 切分。

修正版 colocated 的正式窗口完成 1,930 条，吞吐为 1.6083 Agent/s，正式窗口失败为
0；其中 1,563 条以 final 结束，192 条达到单轮长度上限，175 条达到 16 轮上限。
平均/中位/P90 轮数分别为 5.88/5/13。旧筛选 run 使用会把 WebBackendError 计为整条
失败的 harness，因此这里只保留修正版结果作正式对照。

## 资格规则与后续矩阵

使用同一 c384 数据顺序比较 `Agent/s(new) / Agent/s(no-reverse)`；比值达到 1.8 时视为
“约 2×”，自动补齐 c512/c640 的四方法，形成 3 并发 × 4 方法共 12 组。每组必须满足
预热不少于 299 秒、测量不少于 1199 秒、状态为 `steady_churn` 且正式窗口失败增量为 0；
否则矩阵在该组停止，修复后再续跑。
